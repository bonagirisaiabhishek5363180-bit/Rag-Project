Documentation

Mondroid is an advanced Retrieval-Augmented Generation (RAG) system built to turn static document repositories into an interactive, highly precise knowledge graph.

This documentation outlines the core concepts, architecture, and deployment constraints of the system.

Getting Started

Ensure you have Python 3.10+ installed. Install the dependencies using pip:

pip install -r requirements.txt

You must provide the required API keys (Gemini for generation, and any embedding provider configured in your .env file).

Architecture

Mondroid implements an advanced two-stage retrieval pipeline. It uses ChromaDB for persistent vector storage and a local BM25 index for keyword tracking. This hybrid approach guarantees both semantic understanding and exact-match precision.

Ingestion

During ingestion, unstructured data is processed via the doc_loader.py module. Documents are chunked using recursive character splitting. Overlap is maintained between chunks to preserve context boundaries.

Retrieval

Retrieval occurs in two parallel streams:

  • Semantic: Vector search via ChromaDB using dense embeddings.
  • Lexical: BM25 keyword search to ensure domain-specific terminology is not lost.

The results are merged using Reciprocal Rank Fusion (RRF).

Reranking

The merged candidate list often contains noise. A CrossEncoder model evaluates each candidate chunk individually against the query, generating an absolute relevance score. The list is then truncated to the top-K highest scoring chunks.

Generation

The top-K chunks are injected into the generation prompt. Mondroid uses Gemini models for high-quality reasoning and synthesis, with a fallback mechanism in place to guarantee low-latency responses.

API & Deployment

The system is exposed via a local FastAPI or Flask endpoint (refer to rag_pipe_line.py). When deploying to production, ensure that your persistent ChromaDB directory is mounted to a permanent volume.
